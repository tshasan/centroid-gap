# centroid-gap

Lean 4 proofs and Faiss experiments about one choice in vector search: picking which lists to scan by each list's mean vector.

**Paper:** [paper/main.pdf](paper/main.pdf) (source in [`paper/`](paper/)). Not peer reviewed.

## What this is

An IVF index splits the stored vectors into lists, scores each list by its mean (the centroid), and scans the best few lists. Work is the number of distance evaluations: one per list score plus one per scanned vector. The proofs bound how much work this choice can waste on constructed data. The experiments measure how much a better router wins back on real embeddings.

## Results

Proved in Lean (worst cases on constructed data, not typical behavior):

- **Optimal k-means can be nearly the worst.** On planar data the unique optimal k-means partition, with equal list sizes, costs 1+√N/4 times the work of another equal-size partition at full recall@1. No two equal-size partitions differ by more than 1+√N/2. One bias per list closes the gap. The queries sit far from the data, and direct float32 distances get them wrong.
- **The gap survives cosine search and training.** A winner leading by more than 0.09 in cosine still has its list ranked last. Spherical e-means reaches this partition from warm starts, and from random starts with probability at least p(k) → 1/e.
- **One vector per fixed list has a floor.** On fixed lists that each hold a direction and its opposite, any router with one vector and one bias per list opens at least (k+3)/4 lists on average. The bound is attained. Two vectors per list open one. Real lists we measured have no such pairs.
- **Graph pruning can strand a winner.** In an idealized DiskANN `RobustPrune`, L+3 points isolate a winner with cosine lead above 0.4 for every α in [1, 3/2]; width-L beam search never finds it.

Measured on DEEP and Text-to-Image (1M vectors, 1,000 lists, 95% recall@10):

- **Headroom is large.** An oracle that knows where the answers are did 70% (DEEP) and 83% (Text-to-Image) less work than the centroids.
- **Routers on fixed lists recover little.** Retrained single vectors lost; several vectors per list cut probes but not work. One bias per list (`tools/ivf_tune`) saved 6.0% [95% CI −7.7, −4.3] on DEEP and 8.7% [−10.9, −6.5] on Text-to-Image (6.6% and 11.1% on a second index seed). Test numbers were visible while its defaults were chosen, so this is not a clean held-out test.

## Check the proofs

Lean and Mathlib are pinned at v4.24.0. With [elan](https://github.com/leanprover/elan) (or `nix develop`):

```sh
lake exe cache get                       # prebuilt Mathlib
lake build
lake env lean checks/AuditAxioms.lean    # about 2.5 min
python3 checks/check_ivf_gap.py
python3 checks/verify_graph_conic_theorems.py
```

The audit must end with `Audited 1323 theorem declarations (735 generated by Lean, 588 others).` It fails on any axiom other than `propext`, `Classical.choice` and `Quot.sound`. Theorem index: [docs/verification.md](docs/verification.md).

## Use the bias tuner

`tools/ivf_tune` fits one bias per list for an existing Faiss IVF index from sample queries and picks the probe count. No rebuild.

```python
import faiss, ivf_tune

index = faiss.read_index("my_index.faiss")
tuning = ivf_tune.fit(index, sample_queries)          # a few thousand or more real queries
D, I = ivf_tune.search(index, tuning, queries, k=10)  # same output as index.search
```

It keeps plain centroids when the biases do not help. Expect single-digit savings. [Usage and limits](tools/ivf_tune/README.md)
